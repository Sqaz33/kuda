# Куда

React + Expo приложение на JavaScript для Web, iOS, Android и Telegram Mini App. Пилотный сценарий — совместный выбор кафе, бара или ресторана в Волгограде. [Интеграция с реальным API KG-11](docs/API-INTEGRATION.md), [исторический контракт мока](docs/API.md) и [решения по экранам](docs/DESIGN-NOTES.md) находятся в этом репозитории. Email/MAX в текущем backend отключены.

## Запуск

### С настоящим API (KG-13)

Скопируйте `.env.example` в `.env.local`, задайте `EXPO_PUBLIC_API_URL` — доступный
устройству адрес запущенного бэкенда без `/v1`. Для ссылок приглашений задайте
`EXPO_PUBLIC_WEB_URL` — адрес опубликованного web-клиента. Установите зависимости
через `npm ci` и запустите `npm run web`. Мок одновременно не нужен.
Адреса для разных устройств, CORS и подготовка каталога описаны в
[инструкции интеграции](docs/API-INTEGRATION.md). `.env*` с локальными адресами не коммитятся.

### С учебным моком

```powershell
cd D:\kuda
npm install
npm run mock
```

В другом терминале:

```powershell
cd D:\kuda
npm run web
```

Для iOS/Android: `npm run ios` / `npm run android` с установленным симулятором или Expo Go. Сборка web: `npm run export:web`. Проверки: `npm test`. Экспорт JS для всех платформ: `npx expo export --platform all`.

Мок-сервер использует порт `8787`, сохраняет комнаты только до перезапуска и содержит вымышленные тестовые заведения. Web обращается к порту `8787` на том же хосте, с которого открыта страница; Android Emulator — к `10.0.2.2:8787`, iOS Simulator — к `localhost:8787`. Для телефона в локальной сети запустите мок с `MOCK_HOST=0.0.0.0`, а Expo Web с `--host lan`; оба устройства должны быть в одной сети. Для нативного телефона и настоящего бэкенда задайте `EXPO_PUBLIC_API_URL`. Для корректных пригласительных ссылок задайте `EXPO_PUBLIC_WEB_URL`. Секреты ботов задаются **только** на сервере: `TELEGRAM_BOT_TOKEN`, `MAX_BOT_TOKEN`.

При создании комнаты мок добавляет до двух участников с пометкой «тест» (в пределах выбранного размера компании). После нажатия «Начать выбор» они случайно голосуют за все места и завершают раунд; можно пройти сценарий одному. При входе по приглашению тестовые участники не создаются. Для ручной проверки с несколькими настоящими клиентами запустите мок с `MOCK_DEMO_PARTICIPANTS=0`.

Основной путь: создать комнату → пригласить человека ссылкой или кодом → начать голосование → оценить общий набор заведений → получить совпадения или объяснённый запасной вариант → организатор выбирает место → звонок/сайт/маршрут и ручная отметка брони. В браузере можно вступить по ссылке без установки с гостевым профилем; поиск по коду требует сессии, которую клиент создаёт перед поиском. Telegram передаёт сырую `initData` серверу для проверки подписи. Гость сохраняется на устройстве; повторное имя не восстанавливает прежний профиль. Подробнее — [правила интеграции](docs/API-INTEGRATION.md).

Ограничения перед публичным запуском: нужен настоящий каталог с проверенными правами на фотографии и данные, домен с Universal/App Links, настроенные боты Telegram/MAX, HTTPS API и серверное хранилище. Нативные сборки требуют настроить собственные идентификаторы пакетов и подписи в Expo/EAS.

Статус карточек и отложенные работы: [TASKS.md](docs/TASKS.md).
