# Интеграция клиента с backend KG-11

Проверено по архиву `venue-backend-feat-kg-11-db-api.zip`, полученному 21 октября
2026 года. Серверные источники контракта: `docs/API-MVP.md`, `docs/openapi.yaml`,
HTTP handlers и схемы в `internal/schemas`. `API.md` в этом клиенте сохранён как
история мока; он не отменяет ограничения реального API.

## Подключение

`EXPO_PUBLIC_API_URL` — origin API **без** `/v1`, например `http://localhost:8787`.
Клиент сам добавляет `/v1`. На телефоне нужен доступный адрес компьютера в LAN,
на Android Emulator — `http://10.0.2.2:8787`. Вне локальной разработки нужен HTTPS.
После изменения переменных Expo нужно перезапустить. Значения `EXPO_PUBLIC_*`
видны пользователю; секреты Telegram туда не помещаются.

На backend `CORS_ALLOWED_ORIGINS` должен включать точный web-origin клиента.
Стандартные значения сервера: `http://localhost:8081,http://127.0.0.1:8081`.
Для LAN/другого порта/Telegram Mini App добавить фактический origin. Если мок
занимает 8787, остановить его либо выбрать другой порт API и изменить URL клиента.

Бэкенд не наполняет каталог автоматически. Для изолированной разработки сервер
предлагает явный `docker compose --profile demo run --rm seed` с вымышленными
данными; производственный каталог — отдельная задача. В локальном seed нет
геокодинга произвольных адресов: для проверки формы подходит район Центральный.

## Запросы и ошибки

- Bearer-сессия хранится в SecureStore на телефоне и localStorage в web.
- JSON-запросы содержат только разрешённые поля. Ошибки имеют
  `{error:{code,message}}`; `code` используется для логики, `message` — для человека.
- Успешные ответы 200/201 обрабатываются одинаково. Leave/logout возвращают Ok,
  reports — квитанцию, список комнат — массив Room.
- 401 UNAUTHORIZED сбрасывает просроченную сессию и предлагает вход. Временная
  ошибка `/me` не удаляет сохранённую сессию и не создаёт другого гостя.
- 429 содержит Retry-After; сообщение учитывает его, когда браузер разрешает
  прочитать заголовок. Серверу для web нужно добавить Retry-After к
  Access-Control-Expose-Headers (в архиве открыт только X-Request-ID).
- Голос содержит устойчивый ключ `vote:room:user:venue` и продвигает карточку
  только после успешного ответа. Повтор другого значения не изменяет прежний голос.
- Create/rotate/extend/report/transfer получают ключ операции. После сетевой
  ошибки/5xx/429 повтор того же запроса в текущем процессе использует тот же ключ.
  Успех завершает операцию; следующий намеренный вызов получает новый ключ.
  Ключи незавершённых операций пока не переживают перезапуск приложения.

## Вход и приглашения

В этом API поддержаны гость и Telegram. Email/login, email/register и MAX
возвращают 501 AUTH_METHOD_DISABLED; клиент не предлагает эти способы входа.
Имя не идентифицирует человека: новый guest-запрос создаёт другой профиль.
Сохранённая сессия имеет приоритет над автоматическим входом Telegram, чтобы
запуск Mini App не заменил перенесённый/гостевой профиль.

По длинной ссылке превью доступно без сессии. Перед поиском четырёхзначного кода
клиент получает гостевую сессию. Код живёт ограниченное время; expired-code не
означает отмену длинного приглашения. Preview.access=closed запрещает новому
участнику вход после завершения голосования; действующий участник может вернуться
через idempotent join. Поле code может стать null, это не ошибка формата ответа.

Сервер также предоставляет POST /v1/auth/transfer и /transfer/exchange для
одноразового переноса личности между устройствами. Транспорт добавлен в клиент;
пользовательский сценарий переноса требует отдельного экрана. Ссылка на комнату
сама по себе не переносит персональные голоса.

## Комнаты и раунды

Статусы: waiting → swiping → deciding → selected → completed; отдельно cancelled
и expired. Polling выполняется последовательно с паузой 4 секунды. Ответ комнаты
с revision ниже уже показанной игнорируется.

`candidates` и `ownVotes` содержат историю. Для выбора следующей карточки,
счётчиков и досрочного завершения используются **только** roundCandidateIds.
Карточки availability=withdrawn пропускаются. Порог досрочного завершения:
min(10, число доступных карточек текущего раунда). Один дополнительный раунд
доступен при пустом результате; после extensionCount=1 кнопки продления нет.

Все возвращённые matches показываются без клиентского обрезания до трёх.
Результат объясняет matchMode, incomplete и resultStats (joined, finished,
eligible, quorum): единогласие завершивших не выдаётся за ответы всей компании.

Снятый победитель сохраняется в истории с предупреждением. Хост может явно
заменить его из оставшегося shortlist либо закрыть встречу, если кандидатов нет.
Сохранённая отметка брони не предлагается для повторного изменения; это ручная
отметка организатора, а не внешняя система бронирования.

## Данные каталога и аналитика

Используются photoUrl/null и заглушка без фото. Неизвестные цена/часы/кухня
отображаются как неизвестные. Демонстрационные рейтинг, число отзывов и расстояние
не выдаются за данные API. sourceUrl открывает исходную карточку, если он есть.

Сервер сам регистрирует изменения состояния. Клиент отправляет invite_opened,
invite_shared, fallback_shown и booking_action для внешнего действия. Properties
ограничены roomId, venueId, action; для звонка action=call, для карты action=map.

## Проверка и ограничения

`npm test` запускает тесты API-клиента, правил раундов и прежние тесты мока.
`npm run export:web` проверяет сборку. Эти проверки не подменяют сквозной прогон
клиента с PostgreSQL-сервером и настоящим Telegram. Для него нужны работающий
backend, тестовый каталог, настроенный бот и опубликованный HTTPS Mini App.

Проверка 21 октября 2026: прошли 22 теста, format:check и web export. В headless
Chrome при 414×896 проверены guest перед поиском кода, переход между новыми
карточками второго раунда, вывод всех пяти результатов, объяснение кворума,
недоступность повторного продления и формат аналитики. Проверка браузера выполнена
с локальным моком/ответами по контракту, без настоящего Telegram и PostgreSQL API.
В Go-архиве прошли unit-тесты `./internal/... ./cmd/...`. Сквозной стенд не поднят:
Docker Engine на машине не запущен, адрес тестового API и бот ещё не предоставлены.

### KG-13: повторяемый прогон настоящего API

Следующая проверка 21 октября выполнена уже **без мока**, с Go API из архива,
PostgreSQL/PostGIS и Redis. Docker запущен; создан отдельный compose-проект
`kuda-client-kg13` с собственной базой на 15434, Redis на 16381 и API на 18787.
Применены четыре миграции и явный `seed -demo` из 32 вымышленных заведений.
Рабочие базы не использовались. Серверный код не изменялся.

Команда `npm run test:api` проверяет именно экспортируемый клиент из
`src/api-client.js`, а не отдельную копию запросов. Для запуска нужны две явные
переменные (пример PowerShell):

```powershell
$env:KUDA_TEST_API_URL = 'http://127.0.0.1:18787'
$env:KUDA_ALLOW_TEST_WRITES = '1'
npm run test:api
```

Не направлять этот прогон на production: он создаёт пользователей и встречи.
Автоматически удалять базу он не умеет и не пытается; завершает свои сессии и
закрывает только свои незавершённые комнаты. Аудит и завершённая встреча остаются
в тестовой базе. Тестовому каталогу нужно не менее 22 подходящих мест для второго раунда.

Пройдено: два отдельных гостя, `/me`, анонимное превью, защищённый поиск по коду,
вступление, список комнат, старт и 24 голоса, повтор одного голоса, единогласный
результат, выбор победителя, событие карты и отметка брони. Отдельно проверены
перенос того же профиля, однократность кода переноса, смена приглашения, пустой
результат, новый набор карточек дополнительного раунда и запрет второго продления.
Telegram/MAX этим прогоном не проверяются и по просьбе пользователя отложены.

В реальном справочнике API явно поддержан район `Весь город`; он доступен в форме.
Без заданной переменной web сохраняет протокол страницы (HTTPS не заменяется HTTP),
а локальные адреса эмуляторов остаются отдельными. Для публикации нужно явно
указать HTTPS origin API и пересобрать клиент; порт 8787 — только dev-значение.

В KG-13 также прошли 25 unit-тестов, проверка форматирования и экспорт JS/assets
для web, iOS и Android. Экспорт не равен запуску приложения на физических устройствах
и не создаёт подписанные IPA/APK.
