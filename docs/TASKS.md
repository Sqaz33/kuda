# Карточки клиентской части

## Порядок и границы

Сначала исправления совместимости с архивом KG-11 (коммит `20e45bd`), затем
отдельные коммиты по карточкам. Telegram и MAX отложены по прямой просьбе
пользователя. Учебный репозиторий React не затрагивается.

| Карточка | Состояние | Что проверено / чего не хватает |
| --- | --- | --- |
| KG-13 — связь с бэкендом | Реализовано, локальный API-прогон пройден | Адрес API для web/эмуляторов/телефона, сессия и запросы, реальный Go API + PostgreSQL/PostGIS + Redis, основной сценарий и дополнительный раунд. Публикация требует адресов стенда и CORS. |
| KG-14 — полный прогон Telegram | Отложено пользователем | Нет адреса опубликованного API и настроенного бота/Mini App. MAX также не трогаем. Обычный web-прогон не считается проверкой Telegram. |
| KG-15 — недостающие экраны | Реализован проверенный набор состояний | Повтор стартовой загрузки без потери сессии/приглашения; загрузка/ошибка/пустой список комнат; повтор приглашения или ввод другого кода; перенос профиля, подтверждение смены и выхода; возврат из ожидания. Прогон в Chrome с настоящим API. Новые продуктовые экраны сверх этого набора пока не специфицированы. |
| KG-19 — кабинет владельца | Нужны требования и API | В архиве нет публичных методов владения заведениями, ролей владельца, редактирования и модерации. Пользователь подтвердил, что дополнительных требований пока нет. |
| KG-20 — управление и аналитика | Нужны требования и API | Нет публичных административных методов, выдачи прав, отчётов/агрегаций. Отправка событий `/events` не даёт интерфейс чтения аналитики. |

## Проверки

Команды подключения и воспроизводимого прогона: [API-INTEGRATION.md](API-INTEGRATION.md).
`npm test` не пишет в реальные сервисы; `npm run test:api` требует явного разрешения
тестовых записей через переменные окружения. Секреты и локальные `.env` не коммитятся.

### KG-15: браузерная проверка

21 октября 2026: Chrome, отдельные профили браузера, ширина 414 и 1280 px.
Клиент собран с тестовым Go API на 18787, без мока; PostgreSQL/PostGIS и Redis
работают в изолированном compose-проекте KG-13.

1. Форма создания получила estimate и создала комнату (201).
2. Второй браузер открыл приглашение без сессии, указал имя и вступил.
3. Два клиента отдали по 12 голосов, организатор подтвердил совпадение и отметил
   «Идём без брони»; у второго клиента итог обновился через polling.
4. В профиле создан одноразовый код, третий браузер открыл по нему тот же user.id
   и завершённую комнату. Попытка смены на неверный код потребовала подтверждения
   и показала ошибку, сохранив нынешний профиль.
5. Искусственно прерваны только запросы `/me`, списка комнат и превью; после
   восстановления сети кнопки повтора получили реальные ответы API. Сессия и
   исходное приглашение сохранились. Ошибок JavaScript в браузере не было.

Прошли 25 unit-тестов, `format:check`, `git diff --check` и экспорт web/iOS/Android.
На физических iOS/Android-устройствах приложение в рамках этой проверки не запускалось.

Telegram/MAX и кабинеты владельца/администратора не входят в эти проверки.
