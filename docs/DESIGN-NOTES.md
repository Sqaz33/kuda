# Экраны и решения по макетам

Исходная Penpot-ссылка была предоставлена заказчиком. Penpot MCP в данном сеансе не был доступен как вызываемый инструмент; визуальную основу составили существующий экран проекта и приложенный `docs/14-design.md`. Приоритет имели прямые требования заказчика и `ТЗ-Куда-MVP.md`. Цвета и компоновка взяты из дизайн-документа: тёмный фон, тёплый акцент, Manrope, колонка до 420 px и боковая поясняющая колонка на широком web.

## Реализованный MVP

1. Старт с действиями «Собрать компанию», «Войти по коду», входом и списком своих комнат.
2. Вход/регистрация по почте, вход по подписанным `initData` Telegram/MAX внутри мини-приложений, гостевой вход по имени.
3. Четыре шага создания встречи: время, область, категории и бюджет, компания и дедлайн; проверка числа заведений и действие при недостатке.
4. Превью приглашения с состояниями активной, полной, завершённой и недоступной комнаты.
5. Лобби с участниками, ссылкой/кодом и запуском организатором.
6. Голосование кнопками с прогрессом, деталями заведения, досрочным завершением после 10 оценок, состоянием ожидания и сообщением об ошибке связи.
7. Совпадения с числом голосов, честным большинством и запасным выбором организатора; возможность добавить кандидатов при пустом итоге.
8. Итог с адресом, временем, составом, маршрутом и доступными контактами; ручная отметка о брони без ложного обещания подтверждённого столика.
9. Жалоба на закрытое заведение или неверные данные.

## Логика, уточнённая относительно черновиков

- Для MVP использованы только «Подходит» и «Не подходит». Суперлайк, вето, второй раунд, онлайн-слоты, избранное, круги, история и оценки после визита из более широкого `14-design.md` остаются следующим этапом.
- ТЗ требует минимум 12 кандидатов; комната с меньшим числом не создаётся. При пустом совпадении экран предлагает добавить кандидатов.
- Кандидаты фиксируются сервером при старте. Индивидуальные голоса других участников скрыты до итога. Кворум, большинство и неполное голосование объясняются группе.
- Вход по коду ведёт на превью комнаты, а не сразу в голосование. Ссылка сохраняет контекст комнаты на всех клиентах.
- По приглашению к завершённой встрече показывается общедоступный итог без попытки открыть закрытый API участника.
- Прямой запрос заказчика заменил SMS из раннего дизайн-документа на почту/пароль и добавил MAX.
- Данные тестовых заведений помечены как ориентиры; при отсутствии проверенных часов, фото, телефона и сайта интерфейс не придумывает их.

Список кадров S01–S54 в `14-design.md` охватывает будущий v1. Текущая реализация следует объёму приложенного **MVP** и не выдаёт функции следующего этапа за готовые.
